## 8. Where the run ran, and what it cost

**Locally, 12 workers.** `docs/ops/aws_launch_chain.md` section 12 records a
PASSING Linux parity match, so the cloud path was open -- the PM's decision was
to stay local because the box's throughput reading (83 poss/s/core) came off a
short run dominated by pool startup and `hf_sync_data.py pull` has a path bug
for `engine_inputs` / `model_artifacts`, so a launch risked an hour of setup
against a three-hour window.

| | |
|---|---|
| tag | `F2_2025_s200_rewire1` |
| command | `run_engine.py --fold F2 --season 2025 --seeds 200 --workers 12 --games-per-block 120 --seeds-per-block 5 --time-budget-s 7500` |
| started / wrote | 00:57:39 / 03:08 EDT |
| completed | 500 of 1,920 blocks; **50 complete seeds of 200**; `partial=True` |
| produced | 41,563,946 possessions, 285,500 game rows, 4,516,171 player rows |
| throughput | **5,368 poss/s on 12 workers = 447 poss/s/core**, contended |

That rate is about half the 820-880 poss/s/core engine v0 recorded, and the
difference is contention, not a regression: two other lanes (clock round 4,
rotation round 5) ran their own jobs on the same 20 logical cores throughout.
It is reported as the contended rate it is rather than normalised to a free
box, which this project has never had. **A full 200-seed slate needs ~8.3 hours
at this rate.**

**Two deliberate deviations from the PM's block parameters, both to protect the
read rather than change it.**

1. `--seeds-per-block 5` instead of 25. `run_engine.py` keeps only seeds
   COMPLETE over every game -- a half-finished seed is dropped, never written
   as a thin cell -- so the seed-block size IS the granularity of what survives
   a wall-clock cutoff. At 25 the cutoff discards up to 24 seeds of finished
   work; at 5 it discards up to 4. It cost 17 minutes to restart and bought
   about 25 seeds. Nothing about the simulation changes: RNG is keyed on
   (seed, game_id, family), and batch independence is pinned by
   `test_a_games_draws_do_not_depend_on_the_batch_it_is_in` AND re-proven
   tonight by the parity digest matching bit-for-bit across two worker/block
   splits.
2. `--time-budget-s 7500`, so the run stopped dispatching at 03:02 and wrote by
   03:08 rather than being killed with nothing on disk.

**Code provenance.** The run started at HEAD `4503c52` with the clock lane's
UNCOMMITTED `clock_adapter_v3.py` in the tree, so it is **not reproducible from
any commit** and a paired comparison must run from the same tree. `loop.py` and
`rotation_adapter.py` were edited (rotation round 5) at 01:03 and 01:10, after
all 12 workers had imported them, so the run does not straddle those. Full
account: `results/engine_v0_F2_2025_s200_rewire1_code_provenance.json`. This is
exactly the situation `engine_commit` was added for, one commit too late for
this run; every run from `0cfd68a` on records it automatically.
