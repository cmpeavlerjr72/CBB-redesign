# Box request d1001_F_2: full retrain on the OVERTIME TEAM-FOUL CARRY (`--ot-foul-carry`) x adopted read, FRc / FTc vs the same variants without it, at full size (lane F, 2026-10-01)

Pre-registration of the comparison: this file (no new model class; a data-layer correction, so the read is a carry-vs-no-carry pair, not a bake-off).

**What it is.** The engine carries team fouls from the second half into every overtime (the NCAA men's rule); every foul-state consumer was trained on tables that reset at the OT boundary (96% of OT possessions per fold mismatch). `chain_full_retrain_v1.py --ot-foul-carry` (default off, plan unchanged without it) retrains EVERY consumer on carried columns: possession outcome and clock on `possessions_v4otc` (the PO design and the foul-state overlay on the `v4otc` machine), fg_make and rebound on carried event tables and designs (new stage `otc_designs`), free throw on a carried attempts table (new stage `ft_train`: the free-throw S1 schedule retrained, which the chain otherwise serves unchanged) and the chain serves the retrained FT manifest through the overlay override `adapters.FT_S1_MANIFEST`. The chain's `parity` stage gains an OT-rows check (`diag_ot_carry_parity_v1.py`: carried flag vs an independent recount from the plays, regulation AND overtime rows; FAILS the run on mismatch).

**Variants mirrored from lane D (`d1001_D_1.md`, filed before 12:00 EDT):** F_R and F_T, `--gate-stack adopted`, full gate read 200 seeds at offset 0, reference `v3full_COMB9GCTKD_s200_o0`, floors = D's four S2 draws. The paired comparators are the SAME variants without carry: gate-only reruns on copies of last night's `FR_box_v1` / `FT_box_v2` (exactly D_1 section 2) but with `ENGINE_OT_STATS=1` so the OT columns exist in both arms (that env var is default-off, bit-identical to parity v9 (60 x 5 PASS on this tree), and adds only the columns `{home,away}_ot_{pts,fta,fga,poss}`; it does not change any other column: shared columns equal on 300 x 10 locally). D's own FRa / FTa reads are the same games without the OT columns and may be used as a cross-check of the no-carry arm.

**Local proof done (all on fold 2 / 2022-2025 training seasons; nothing sealed):**
- Default path rebuilt from raw equals the stored tables value for value (fg events 2,241,195 rows, rebound events 1,549,406, FT attempts 809,294: every column equal; `equals()` differs only by dtype).
- Carried tables: regulation rows identical to the stored ones in every table and the designs (0 regulation rows differ); OT rows differ: fg events 17,253 of 17,660, rebound events 13,511 of 13,801, FT attempts 14,322 of 14,521. `possessions_v4otc` regulation rows are `DataFrame.equals` to `possessions_v4` in all four seasons (audit part 2).
- OT parity stage: carried fg and rebound events vs the independent recount: 0 of 15,327 / 0 of 10,794 joined OT rows mismatch, 0 of 2.0 M / 1.3 M regulation rows; the NEGATIVE control (the stored, reset table) fails with 97.6% of OT rows mismatched.
- Chain: default dry-run plan byte-identical to HEAD~ (both variants, 56 lines); carry dry-run lists every new stage; carried smoke of `fg_design, fg_train, rb_design, rb_train` on the carried designs PASS (log `results/otc_smoke_chain.log`); `ft_train` ran locally end to end (452 s on one core; its manifest loads through the overlay override).
